# Wayfinder map — v0.6 ocr-structure

## Destination

OCRed pages (scanned pdf + djvu) emit the same structural IR as native
pdf/docx: `blocks` (at minimum `TableBlock` with rows; headings as far as
cheaply possible) on `PageResult` — so LLM/RAG/semantic-search renderers can
chunk project documentation and scientific journals without flattened,
cell-scrambled tables. Means: our own code and/or lightweight third-party
modules (onnxruntime-scale, e.g. RapidAI TableStructureRec — a candidate, not
a commitment); NO heavy AI parsers (carried: docling/unstructured stay out).
Cloud engines (glm) may participate only as opt-in, never the default path.
Renderers themselves are NOT this map — a later effort.

STATUS: completed 2026-09-14 — destination reached, no open tickets.

## Notes

- Domain: `pdf-router` Python project (uv, Python ≥ 3.12); sole consumers are
  local RAG indexing pipelines. Ethos: "ultra-minimal, deterministic,
  deploy-anywhere" (`pyproject.toml`).
- Skills per session: `grilling` (one question at a time), `domain-modeling`
  (when a term graduates), `research` subagent (outside-knowledge tickets).
- Reply style: short, plain language (user has ADHD); compact question
  packages; ground claims in checked facts.
- Standing preferences carried from v0.4/v0.5 (do not re-litigate):
  - No heavy AI parsers (docling, unstructured, ...) — minimal resources.
  - Cloud OCR allowed only as opt-in engine; default stays local (rapidocr).
  - Flat functions; one file over many; tunables in TOML config.
  - Format dispatch seam locked (commit 57cfa1f): magic bytes → `_INSPECTORS`.
  - Raster seam locked per ADR-0004: `rasterize.py` is the only raster
    acquisition point (pdf→pymupdf, djvu→ddjvu); engines keep signatures.
  - Images as sidecar paths, not base64 in IR (TKT-RT-08).
  - User commits via `gaa && forge commit && gp` — leave changes uncommitted.
  - `uv run python` / `uv run pytest`; never two pytest runs in parallel;
    shell hard deadline 5 min — long jobs via `nohup ... &` + poll.
- Destination-user wording (2026-09-13): "collect everything, lose nothing,
  spend minimum resources"; exact cell-corner coordinates are nice only if
  resource-cheap — semantic integrity of tables/headings beats bbox precision.
- Established fact base for this map:
  - OCR result lands in `page.markdown` only (`core.py:236`); `blocks` stays
    `[]` for every OCR page — deliberate v0.3–v0.5 limitation.
  - Default engine rapidocr returns lines only; but `result` also carries
    per-line boxes + scores that v1 discards (`ocr.py:211-215`).
  - pdf-inspector's local OCR models are PP-OCRv6 det+rec (structure-free);
    its structure machinery is native-path-only (structure tree / font size).
    `pdf_inspector_ocr` OCR output = markdown, no structure either.
  - glm_ocr (`md_results` + `layout_details` with `label=table|title` bboxes
    and HTML tables) is the one engine whose raw output already carries
    structure — cloud-only today.
  - Native tables parse as pipe-tables from markdown into `TableBlock.rows`
    (existing code, reusable for any pipe-table source).
- Golden anchors named by user (2026-09-13), in
  `~/vbrdb/orchestrator/downloads/` (930 files):
  - `Генетические_аспекты_разведения_сиговых_ры_11188.pdf` — raster pdf,
    tables on pp. 15 and 34 (1-indexed; 248 MB);
  - `Рыбы_бассейнов_Нижнего_Дона_и_Кубани_11138.pdf` — Soviet book scan,
    table on p. 14 (155 MB; disk name verified 2026-09-13);
  - many native-pdf journals in the same dir — native-vs-OCR comparison
    pairs for quality gates;
  - project-documentation scans — the other persona (djvu corpus already
    covered by v0.5 anchors).

## Decisions so far

- [Destination grilling, pre-map 2026-09-13](#) — structure into IR blocks
  (same contract as native pdf/docx); tables first (cell scrambling is the
  pain), headings next, cheaply; journal + book + project-doc anchors named;
  means open: own code vs lightweight third-party (RapidAI candidate).
- [TKT-ST-01 — Research: local table-structure & heading recovery](tickets/TKT-ST-01-ocr-structure-tooling-research.md)
  — **RapidAI stack fits every constraint: wired_table_rec (unet 8.3 MB
  onnx) + lineless_table_rec + table_cls, Apache-2.0, pure-py wheels,
  py3.12-ok, accepts our rapidocr `ocr_result` (boxes+txts+scores) — adds
  ~0.1–0.5 s/page after 23–40 s OCR. Output has `logic_points` = direct
  row/col spans for `TableBlock.rows`. Headings: box-height heuristic from
  rapidocr boxes is the only cheap local option (no viable local title
  model; DocLayout-YOLO AGPL+torch, PP-Structure paddle-tax). glm
  layout_details = opt-in cloud structure (HTML tables, vision_title,
  ~1.8k tok/page, non-deterministic). Pure-CV line projection = free
  fallback. Risks to retire in probe: rapidocr version-window mismatch
  (wheels declare no rapidocr dep — advisory), model_type pin churn.**
  Evidence: [research/ocr-structure-tools.md](research/ocr-structure-tools.md).
- [TKT-ST-02 — Anchor survey](tickets/TKT-ST-02-anchor-survey.md)
  — **both scanned anchors verified (scanned 0.95; 642 pp / 109 pp); OCR
  probe on Рыбы p. 14 shows the exact pain (167 lines, columns
  interleaved, zero structure); native journal pairs found under
  English-named files (table pages 3/4/6 and 5/6/8/9); CAVEAT: most
  `10.*_*.pdf` names are HTML dumps, magic-check every anchor; djvu =
  ~230-pp chapter splits, tiny text layers, table-spotting = HITL.**
  Evidence: [research/structure-anchors.md](research/structure-anchors.md).
- [TKT-ST-03 — Approach: how OCR pages acquire structure](tickets/TKT-ST-03-structure-approach.md)
  — **hybrid C locked: default = one structure pass over the rapidocr
  result (boxes v1 discards); glm `layout_details` short-circuit when
  present; pipe-parse fallback for boxless engines; new `structure.py`
  seam (`structure_page`, `blocks_from_glm`, lazy singleton); table
  engine default `lineless` — live probe: on Рыбы p. 14 wired unet
  recovers only the ruled header (8 cells) while lineless recovers the
  mixed page (144 cells); wired/auto stay TOML values; headings via
  box-height heuristic in v1; OCR raster reused, no second rasterize.
  Measured: lineless adds 7.3–7.7 s/page on top of 22–24 s OCR.**
  Evidence: [research/ocr-structure-tools.md](research/ocr-structure-tools.md)
  (§ Live probe).
- [TKT-ST-04 — IR contract for OCR-sourced blocks](tickets/TKT-ST-04-ir-contract-ocr-blocks.md)
  — **five IR deltas locked: provenance sources (`ocr_table_lineless` /
  `ocr_table_wired`, `ocr_pipe_fallback`, `ocr_glm_layout`,
  `ocr_box_height`); bbox optional, raster pixels, no point-scaling;
  IR 0.4 → 0.5; scan headings = `HeadingBlock.level` ∈ {1, 2} with
  TOML-tunable height ratios; `TableBlock` unchanged (no per-cell
  confidence). Implementation lands in TKT-ST-07.**

- [TKT-ST-05 — Quality bar: golden anchors for OCR structure](tickets/TKT-ST-05-quality-bar.md)
  — **two-tier v0.5 pattern + one middle gate: slow tier = corpus-path
  anchors (Рыбы p. 14, Генетические pp. 15/34, two native-vs-OCR journal
  pairs; no djvu table anchor — shared scan path covers it); table
  invariant = fuzzy-substring on named cells + row/col counts from
  `logic_points` + header tokens (exact match never; scan noise proven);
  fast tier = stub, PLUS a committed ~100 KB crop of the Рыбы p. 14
  table running the live lineless engine as a middle gate (crop produced
  and wired in TKT-ST-07); determinism = pinned wheels + fixed
  onnxruntime threads + vendor auto-download; perf gate = structure ≤ 15
  s/page (measured 7.3–7.7 s).**

- [TKT-ST-06 — ADR-0005: OCR structure](tickets/TKT-ST-06-adr-0005-ocr-structure.md)
  — **ADR-0005 written (`docs/adr/0005-ocr-structure.md`, Accepted
  2026-09-14): hybrid pass locked with all sub-decisions, seven
  alternatives rejected with reasons, dependency ruling (two pinned
  Apache-2.0 wheels, ModelScope auto-download), IR 0.5, quality bar
  referenced; implementation checklist = TKT-ST-07's file list.**

- [TKT-ST-07 — Implement OCR structure](tickets/TKT-ST-07-implement-ocr-structure.md)
  — **done 2026-09-14, all gates green (fast suite 198 passed; slow tier
  5 passed). `structure.py` seam landed (span-aware grid from `pred_html`
  — replaced the bench's `zip(cells, logic_points)`, which was wrong:
  124 `<td>` vs 53 anchor-only `logic_points` in arbitrary order);
  `ocr_page` → `(markdown, engine, blocks)` triple, glm short-circuit,
  pipe fallback for boxless engines; IR 0.5 with five provenance tags;
  `[structure]` TOML section; three-tier tests + committed crop fixture
  (re-shot with the header band). Live anchors: Рыбы p.14 grid 42x6
  (caption row 0, header rows[1]), Генетические p.34 grid 41x7; p.14 is
  a full-page table (zero headings asserted — no false positives);
  structure-only perf 7.4 s vs 15 s gate.**
  Evidence: `tests/test_structure.py`, resolution in the ticket.
