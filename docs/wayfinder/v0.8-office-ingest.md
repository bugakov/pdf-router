# Wayfinder map — v0.8 office-ingest

## Destination

The office formats the corpus actually contains — **xlsx (89 files) and
legacy .doc (~100 files, OLE2 + 7 HTML-with-.doc-extension + 2 lock files) —
ingested into the IR as working code**, following the v0.4 pattern: research
grounds the decisions, grilling locks the semantics, ADR-0008 records them,
then the inspector(s) land behind the existing `_INSPECTORS` seam with
golden-anchor quality bars on real corpus files. xlsx gets a native stdlib
parser (zipfile + ElementTree, like docx); the `.doc` path is chosen by
research evidence and may honestly end in Out of scope if no candidate
passes the project's decision rule (user decree 2026-09-28: "Research
решит"). The format gate (`formats.py`) learns OLE2 and xlsx sniffing;
renderers are not touched — they consume the IR unchanged.

STATUS: completed 2026-09-28 — destination reached, no open tickets
(all tickets OI-01…OI-09 resolved; quality bar incl. slow anchors F3 +
276 MB; 307 fast tests + 2 slow, ruff, mypy clean).

## Notes

- Domain: `pdf-router` Python project (uv, Python ≥ 3.12); sole consumers
  are local RAG indexing pipelines. Ethos: "ultra-minimal, deterministic,
  deploy-anywhere" (`pyproject.toml`).
- Skills per session: `grilling` (one question at a time),
  `domain-modeling` (when a term graduates), `research` subagent
  (outside-knowledge tickets).
- Reply style: short, plain language (user has ADHD); compact question
  packages; ground claims in checked facts.
- Standing preferences carried from v0.4–v0.7 (do not re-litigate):
  - No heavy AI parsers (docling, unstructured, ...) — minimal resources.
  - Flat functions; one file over many; tunables in TOML config.
  - Images as sidecar paths, not base64 in IR (TKT-RT-08).
  - `uv run python` / `uv run pytest`; never two pytest runs in parallel;
    shell hard deadline 5 min — long jobs via `nohup ... &` + poll.
  - Research experiments never touch `pyproject.toml` / `uv.lock`
    (`uv run --no-project --with <pkg> …` or an ephemeral venv).
  - User commits via `gaa && forge commit && gp` — leave changes
    uncommitted.
  - External binaries: rejected for docx (ADR-0003), admitted for djvu
    (`djvulibre-bin`, ADR-0004) — the ruling is per-format, decided with
    evidence, NOT a global ban. `.doc` is not pre-ruled either way.
- Established fact base for this map (checked 2026-09-28):
  - **Corpus = `/home/scanum/kotel-zamechanna`** (recursive count):
    50 pdf, **89 xlsx**, 26 docx, **~100 .doc**, 40 md, 7 html, ...
    No pptx/xls/ppt/odt/rtf anywhere.
  - **xlsx**: all sampled files are valid OOXML zips; 172 worksheets total;
    126 sheets contain `<mergeCell>`; 17 sheets contain `<f>` formulas;
    60/60 sampled have `xl/sharedStrings.xml`; 0 media in sample;
    15/60 sampled are multi-sheet; smeta files like `ЛСР.xlsx` carry 10+
    named sheets (`Блочно-модульная котельная - ЛС`, `Сети
    электроснабжения`, ...) with title rows merged full-width
    (`A13:P13`) alongside data merges (`A10:F10`, `G10:P10`);
    largest = 1.2 MB (`ЛСР.xlsx`), sheet1 XML up to ~400 KB,
    dimension up to `A1:IG465`.
  - **.doc**: ~90 files with OLE2 magic `d0cf11e0a1b11ae1`; 7 files are
    HTML (`<!DOCTYP…`) with a `.doc` extension (laws: 190-ФЗ, 7-ФЗ,
    44-ФЗ, ПП-145/1034/87, 384-ФЗ); 2 files are Word lock files
    (`~$…`, 162 B); sizes from 32 KB to **276 MB** (`ООС Котельная
    Опухлики СЗЗ_ред 4_2.doc`) — the big ones are image-heavy project
    texts (`00847…ИЭИ (4).doc` = 67 MB, `…ИЭИ` variants 115–118 MB).
  - Format gate today (`formats.py:103-142`): zip → `_sniff_zip`
    returns DOCX only if `word/document.xml` present, otherwise raises
    "OOXML package that is not a docx (xlsx/pptx?)"; OLE2 and HTML
    fall through to "unrecognized file format". `Format` enum has
    PDF/DOCX/DJVU (`formats.py:51-56`); `_INSPECTORS` at `:90-94`.
  - docx adapter (`adapters/docx.py`, 629 lines, stdlib only) is the
    template: `extract_ir(path) -> IR`, one page (`page=0`),
    `SourceTool`-provenanced, `Metadata.source_format`, tolerant XML
    helpers (`_read_xml`, `_load_rels`), table grid with
    gridSpan/vMerge-unwrap, pipe-markdown generated from the same rows,
    media → sidecar, `docx_info()` for `--info`.
  - IR: `IR_VERSION = "0.5"` (`ir.py:60`); `Metadata.source_format`
    default `"pdf"` (`ir.py:110`); `SrcTool` enum `ir.py:63-73`
    (PDF_INSPECTOR, RAPIDOCR, …, DOCX_ADAPTER, DJVU_ADAPTER);
    `core.py:213` runs the text/OCR pass only for `source_format in
    ("pdf", "djvu")`; `core.py:284` dispatches image extraction
    per source_format; `cli.py:95-107` `--info` "one door".
  - Renderers are pure `(ir, *, config) -> str`, may not import
    adapters (`tests/test_conventions.py:37`); `md` renderer
    concatenates `pages[].markdown`, `chunks` splits by `##`–`####`
    headings and subtracts `TableBlock` regions — both must keep
    working untouched.
  - Precedents to reuse verbatim: ADR-0003 (native parse decision rule
    "quality ≥ native AND deps ≤ native"; alternatives survey),
    ADR-0004 (per-format external-binary ruling via research),
    `docs/wayfinder/research/docx-tools.md` (the research-doc template).
  - OfficeReadCpp (RapidAI) assessed pre-map: **no LICENSE file**,
    0.1.0/4 commits, C++20 with no Python bindings, output is
    text/markdown only (no structured rows, no heading levels) — a
    candidate to *measure* in TKT-OI-01, not a default.

## Out of scope

- pptx, xls, ppt, odt, rtf, epub: not present in the corpus
  (recursive count 2026-09-28); the current typed rejections stay.
- HTML as a full routed format (rich parsing, structure, links): the
  TKT-OI-04 verdict landed on a *minimal* stdlib text ingest for the 7
  HTML-with-`.doc` files (`source_format="html"`); anything beyond
  tag-stripped prose is not this map's destination.
- xlsx media/charts/drawings/comments — researched out: 0 of each in
  all 89 corpus files (TKT-OI-02 area 6), so v1 extracts none; graduates
  only if the corpus grows such files.
- Renderer changes: `md` / `chunks` / `json_renderer` must consume the
  new formats through the existing IR contract; any renderer upgrade is
  a later effort (as in v0.7).
- OCR for office files: scanned-docx/xlsx handling remains the
  documented ADR-0003 limitation unless TKT-OI-04 explicitly reopens it.
- RAG/zvec/embedding side — consumer territory, unchanged since v0.7.
