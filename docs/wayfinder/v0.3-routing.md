# Wayfinder map — v0.3 routing pipeline

## Destination

v0.3 routing pipeline that takes a PDF and emits IR 0.2 plus paths to extracted images for RAG indexing, implemented as flat functions (no Adapter classes), with `looks_like_text` as the only new predicate on the text path.

## Notes

- Domain: `pdf-router` Python project, sole consumer is local RAG indexing pipelines.
- Skills to consult per session: `grill-me` (one question at a time), `grilling` (deep interview), `domain-modeling` (when a new term graduates), `prototype` (when a concrete artifact will unblock the discussion).
- Standing preferences (locked across the project, do not re-litigate):
  - **No premature abstractions.** No classes unless one is strictly required; no Protocols, no enums, no adapter wrappers. Talk in concrete names: `pdf-inspector`, `pymupdf`/`fitz`, `tesseract`, `glm-ocr`, `deepseek-ocr-2`, real file paths, real pages.
  - **Procedural style.** `if/elif` chains in top-level functions, not OOP hierarchies.
  - **One file over many** unless size/complexity truly demands split.
  - **No caching, no premature optimization.** 16s on a 17 MB PDF is acceptable.
  - **No `[routing]` hardcodes.** All routing tunables live in `[routing]` TOML section and are parsed by `RoutingConfig`.
  - **Images stored as paths to PNG in a sidecar folder**, not base64 inside IR.

## Verification after session close

End-to-end smoke on `/tmp/pzu_test.pdf` (20 pages, mixed text + 21 raster photos) uncovered four real regressions that the unit tests had not caught:

1. `extract_raster_photos` indexed `PageResult` (our IR class) instead of `pymupdf.Document`, returning `page is None` for every page.
2. `pix["image"].tofile(...)` — `image` is `bytes`, not a Pillow `Image`. `write_bytes()` was the fix.
3. **`process_pdf` race condition**: `for page_num, (img_fut, txt_fut) in futures.items()` rebound the loop variable `page` to the last page only, so 19 of 20 pages received empty `page.images`. Fixed by storing `(page, img_fut, txt_fut)` tuples in a list.
4. `extract_vector_diagrams` opened `pymupdf.open(pdf_path)` once per drawing (N+1). Collapsed to a single doc.

All four fixed and protected by `tests/test_extract_images.py` (6 tests) and `tests/test_cli_smoke.py` (4 tests). **Final test count: 68 unit + 4 e2e = 72 passed, 3 deselected (slow, need pdfium+ort runtime libs).**
