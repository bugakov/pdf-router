# Wayfinder map — v0.7 rag-chunks

## Destination

The `chunks` renderer rebuilt (clean break — the legacy flat-text
contract and its tests are deleted, no compat mode) into a RAG-first
chunker over IR 0.5: one JSONL schema for `text` / `table` /
`table_part` chunks, where a table chunk = context (title + caption) +
markdown table + facts summary; the embed-text is assembled by the
renderer itself (key-value linear form for tables, context-prefixed
text for prose — the consumer just embeds the `embed` field); big
tables split by rows with the header duplicated (`table_id` + part
numbering). Verified on the v0.6 golden anchors (Рыбы p. 14,
Генетические p. 34, native journal pairs) and ruled in ADR-0006.
zvec itself is NOT installed here — this map fixes the chunk contract
the future zvec ingestion will eat.

STATUS: completed 2026-09-14 — destination reached, no open tickets
(all tickets RC-01…RC-08 resolved; quality bar 20/20 incl. slow
anchors; full default suite 216 passed).

## Notes

- Domain: `pdf-router` Python project (uv, Python ≥ 3.12); sole consumers are
  local RAG indexing pipelines. Ethos: "ultra-minimal, deterministic,
  deploy-anywhere" (`pyproject.toml`).
- Skills per session: `grilling` (one question at a time), `domain-modeling`
  (when a term graduates), `research` subagent (outside-knowledge tickets).
- Reply style: short, plain language (user has ADHD); compact question
  packages; ground claims in checked facts.
- Standing preferences carried from v0.4–v0.6 (do not re-litigate):
  - No heavy AI parsers (docling, unstructured, ...) — minimal resources.
  - Cloud only as opt-in (glm); the default path stays local and
    deterministic — includes chunk summaries (LLM summary is NOT the
    default; see fog).
  - Flat functions; one file over many; tunables in TOML config.
  - Images as sidecar paths, not base64 in IR (TKT-RT-08).
  - User commits via `gaa && forge commit && gp` — leave changes uncommitted.
  - `uv run python` / `uv run pytest`; never two pytest runs in parallel;
    shell hard deadline 5 min — long jobs via `nohup ... &` + poll.
- Renderer doctrine (unchanged): a renderer is a pure function
  `(ir, *, config) -> str`; renderers may not import adapters
  (`tests/test_conventions.py:37`). `PageResult.markdown` stays the
  authoritative text; `blocks` is the structural decomposition the new
  renderer consumes for tables/context.
- Established fact base for this map:
  - Current `chunks.py` renders flat text from `page.markdown` only and
    never reads `blocks` (`renderers/chunks.py:83-105`); chunk keys:
    chunk_id/text/page/section/src_tool/error/images; token heuristic
    `len(text) // 4`; split with overlap.
  - IR 0.5: OCR pages carry real `TableBlock` (markdown verbatim-pipe,
    `rows` grid, `header_rows`, raster-pixel `bbox`, `source`
    provenance) and `HeadingBlock` (levels {1,2} on scans,
    `ocr_box_height`). Native pages: `markdown_pipe` /
    `structure_tree` / `font_size_fallback` / docx-style blocks.
  - `structure_page` returns blocks as [tables..., headings-by-y] — NOT
    reading order; per-page re-ordering is the renderer's job.
  - Anchors: Рыбы p.14 grid 42x6 — row 0 is a caption («Таблица 14 —
    ...»), real header is row 1; Генетические p.34 grid 41x7; a ~100 KB
    crop fixture of Рыбы p.14 runs the live lineless engine in tests.
  - Doc identity: 12-hex SHA-256 of the absolute path (TKT-RT-12) — the
    sidecar images folder name; IR has no path field today
    (`Metadata.title` only, often None on scans).
  - Config: `ChunksConfig` = max_tokens 512 / overlap_tokens 64;
    `_KNOWN_CHUNKS_KEYS` validates `[renderers.chunks]`.
  - No research tickets needed: the RAG doctrine is the user's
    (hybrid chunk = header/context + markdown table + LLM-style
    summary; KV linear form for embeddings; markdown for generation;
    no colspan/rowspan — the IR grid is already flat), and zvec is out
    of scope by decree.

  tables stay whole unless over budget → row-split with duplicated
  header + `table_id`/part; single chunk envelope with renderer-built
  `embed` (KV form for tables, context-prefixed prose) + `markdown`
  for generation; context = deterministic walk-back over HeadingBlocks
  across pages + breadcrumbs (no surrounding-paragraph mining in v1);
  IR delta: additive `Metadata.source_path`, `doc_id` = 12-hex sha256,
  no version bump; caption-row demotion rule for key selection (Рыбы
  row-0 case); double-emission solved by source-wise subtraction
  (native = exact-match vs `TableBlock.markdown`, OCR = pipes yield to
  blocks); embed preamble for text chunks, `embed_context` TOML flag;
  quality bar = fast/middle(crop fixture)/slow(anchors) tiers.

## Out of scope

- glm table summary (opt-in engine behind the RC-01 `summary` seam,
  reusing the glm_ocr channel) — did not graduate before the map
  closed; the config still reserves the value (`"glm"` → ConfigError
  until implemented).
- zvec setup/integration, multi-vector retriever mechanics, embedding
  models — consumer side; the chunk contract only carries enough fields
  (per-row KV + `table_id`) for the user's pipeline to do multi-vector
  if it wants.
- `md` renderer upgrade (block-substituted tables for human reading) —
  document persona, a later effort; here only `chunks` is rebuilt.
- Surrounding-paragraph context mining (`surrounding_context` of the
  original doctrine) — rejected for v1: heading + facts summary cover
  linking; paragraph heuristics on scans are not resource-cheap.
- Heavy AI parsers, new OCR engines, vbrdb orchestrator — carried.
